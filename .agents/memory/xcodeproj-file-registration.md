---
name: Registering new Swift files in the Xcode project from Replit
description: How to keep Pluma.xcodeproj valid when adding source files in the Linux workspace
---

The Xcode project is generated by xcodegen from `project.yml` (folder globs), but xcodegen cannot run in the Replit Linux environment. New Swift files therefore silently miss the build unless registered.

**Why:** A code review of a completed feature failed solely because new model/test files were untracked in `project.pbxproj` — the app would not compile on a Mac despite correct Swift code.

**How to apply:** After adding/removing Swift files, register them with the python `pbxproj` package (`pip install pbxproj`), e.g. `p.add_file(path, parent=p.get_groups_by_name('Models')[0], target_name='Pluma')` (tests → target `PlumaTests`). The next `xcodegen generate` on a Mac normalizes any cosmetic differences. Never hand-edit the pbxproj text.

Merge conflicts: when merging branches where both sides added files, the generated `project.pbxproj` conflicts — resolve with `--ours`, then register the other side's new Swift files via the python `pbxproj` package as above (a Mac-side `xcodegen generate` also fixes it).

Also: the repo's `return switch` expressions are Swift 5.9+; the local swift 5.8 toolchain's `-parse` flags them as false-positive syntax errors — usable for syntax checks of new code, but ignore those.

Prompt-composition convention (this codebase): builder/directive chains must emit the byte-identical legacy prompt when the chain equals its model's `defaultChain`, so untouched installs behave exactly as before.
